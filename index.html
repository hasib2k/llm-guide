1WorkstationAI মডেল চালানোর মতো শক্তিশালী কম্পিউটার।

A powerful computer capable of running AI models.

  • ভেতরে থাকে শক্তিশালী CPU, এক বা একাধিক Graphics card (GPU), অনেক RAM আর দ্রুত SSD।Inside: a strong CPU, one or more graphics cards (GPUs), lots of RAM and a fast SSD.
  • সাধারণ ল্যাপটপে বড় মডেল চলে না বা খুব ধীরে চলে; তাই লোকাল মডেল চালাতে workstation লাগে।Ordinary laptops can’t run big models, or run them very slowly, so local models need a workstation.
  • কেনার আগে দেখো কোন আকারের মডেল চালাবে, আর তার জন্য কত VRAM লাগবে।Before buying, decide which model size you will run and how much VRAM it needs.

2Graphics card (GPU)হাজার হাজার ছোট হিসাব একসাথে করতে পারে, তাই AI মডেলের আসল কাজ এটাই করে।

It can do thousands of small calculations at once, so it does the real work of an AI model.

  • CPU-তে অল্প কয়েকটা শক্তিশালী core, GPU-তে হাজার হাজার ছোট core।A CPU has a few powerful cores; a GPU has thousands of small ones.
  • মডেলের কাজ মূলত কোটি কোটি গুণ-যোগ, যেটা একসাথে করতে GPU অনেক দ্রুত।A model’s work is mostly billions of multiply-adds, which a GPU does far faster in parallel.
  • NVIDIA বেশি জনপ্রিয়, কারণ প্রায় সব AI টুল তাদের CUDA সমর্থন করে।NVIDIA is the most popular because almost every AI tool supports its CUDA.

3VRAMGraphics card-এর নিজস্ব দ্রুত মেমোরি। মডেল চালানোর সময় এখানেই থাকে।

The graphics card’s own fast memory. The model lives here while it runs.

  • VRAM যত বেশি, তত বড় মডেল চালানো যায়।The more VRAM, the bigger the model you can run.
  • মোটামুটি হিসাব: 7B–8B মডেলের ছোট করা (Q4) সংস্করণে প্রায় 4–5GB VRAM লাগে।Rough guide: a compressed (Q4) 7B–8B model needs about 4–5 GB of VRAM.
  • মডেল VRAM-এ পুরো না ধরলে কিছু অংশ RAM-এ চলে যায়, তখন অনেক ধীর হয়।If the model doesn’t fit in VRAM, part of it spills into RAM and it becomes much slower.

4RAMকম্পিউটারের মূল মেমোরি। VRAM-এর চেয়ে বড় আর সস্তা, কিন্তু AI-এর কাজে ধীর।

The computer’s main memory. Bigger and cheaper than VRAM, but slower for AI work.

  • মডেল ফাইল প্রথমে SSD থেকে RAM-এ আসে, তারপর VRAM-এ যায়।A model file goes from the SSD into RAM first, then into VRAM.
  • GPU না থাকলে মডেল RAM-এ রেখে CPU দিয়েও চালানো যায়, তবে অনেক ধীরে।Without a GPU, a model can run from RAM on the CPU, but much more slowly.
  • VRAM কম হলে RAM বাড়তি জায়গা দেয়, কিন্তু গতি কমে যায়।When VRAM is short, RAM provides extra room, but speed drops.

5Framework: Ollama, LlamaLlama হলো Meta-র একটা মডেল পরিবার; Ollama হলো নিজের কম্পিউটারে মডেল চালানোর টুল।

Llama is Meta’s family of models; Ollama is a tool for running models on your own computer.

  • Ollama মডেল ডাউনলোড করে, VRAM-এ লোড করে আর চালায়; যেমন “ollama run qwen”।Ollama downloads a model, loads it into VRAM and runs it, for example “ollama run qwen”.
  • এটা একটা লোকাল API দেয় (localhost:11434), তাই নিজের অ্যাপ থেকে মডেলকে প্রশ্ন পাঠানো যায়।It provides a local API (localhost:11434), so your own app can send questions to the model.
  • নাম মিলে গেলেও গুলিয়ো না: Llama হলো মডেল (চিন্তা করে), Ollama হলো টুল (চালায়)।Don’t confuse the names: Llama is the model (it thinks), Ollama is the tool (it runs it).

6Model (Qwen, Gemma…)প্রচুর লেখা পড়ে শেখা AI ব্রেইন, যে পরের শব্দ অনুমান করে করে উত্তর বানায়।

An AI brain trained on huge amounts of text that builds answers by predicting the next word.

  • উদাহরণ: Qwen, Gemma, Llama, Mistral, DeepSeek; আর API-তে GPT, Claude।Examples: Qwen, Gemma, Llama, Mistral, DeepSeek; and through APIs, GPT and Claude.

7Parametersমডেলের ভেতরের শেখা সংখ্যাগুলো। 8B মানে 800 কোটি parameter।

The learned numbers inside a model. 8B means 8 billion parameters.

  • প্রতিটা parameter একটা ছোট নবের মতো; ট্রেনিংয়ে কোটি কোটি নব ঘুরিয়ে ঠিক জায়গায় বসানো হয়েছে।Each parameter is like a small knob; training turned billions of knobs to the right positions.
  • Parameter বেশি হলে মডেল সাধারণত বেশি স্মার্ট, কিন্তু বেশি VRAM লাগে আর ধীর চলে।More parameters usually mean a smarter model, but it needs more VRAM and runs slower.
  • 1B–3B ছোট ও দ্রুত, 7B–14B মাঝারি, 70B+ বড় ও ভারী।1B–3B is small and fast, 7B–14B is medium, 70B+ is large and heavy.

8Cold startমডেল প্রথমবার চালু হতে যে দেরি হয়, কারণ ফাইলটা মেমোরিতে তুলতে হয়।

The delay when a model starts for the first time, because its file must be loaded into memory.

  • প্রথম প্রশ্নে মডেল ফাইল SSD → RAM → VRAM পথে লোড হয়; বড় মডেলে কয়েক সেকেন্ড থেকে এক মিনিট লাগে।On the first question the model loads SSD → RAM → VRAM; for a big model this takes seconds to a minute.
  • লোড হয়ে গেলে কিছুক্ষণ মেমোরিতে থাকে (Ollama-তে ডিফল্ট প্রায় 5 মিনিট), তখন উত্তর দ্রুত আসে।Once loaded it stays in memory for a while (about 5 minutes by default in Ollama), so answers come fast.
  • কমানোর উপায়: দ্রুত SSD, ছোট মডেল, আর মডেল সবসময় লোড করে রাখা।To reduce it: a fast SSD, a smaller model, and keeping the model loaded.

9Orchestrationপুরো সিস্টেমের ম্যানেজার। কোন কাজ আগে, কোনটা পরে, আর কিছু ভুল হলে কী করতে হবে, সব সে ঠিক করে।

The manager of the whole system: it decides what runs first, what runs next, and what to do when something fails.

  • কাজ কয়েকভাবে সাজানো যায়: একটার পর একটা, কয়েকটা একসাথে, প্রশ্নের ধরন দেখে আলাদা পথে, বা কাজ শেষ না হওয়া পর্যন্ত বারবার।Work can be arranged in several ways: one after another, several at once, different paths by question type, or repeating until done.
  • কোনো ধাপ ব্যর্থ হলে আবার চেষ্টা করা, বেশি সময় নিলে থামানো, আর কতবার চেষ্টা করা যাবে তার সীমা, এসবও সে সামলায়।It also handles retrying failed steps, stopping steps that take too long, and limits on how many tries are allowed.
  • যতটুকু সম্ভব ধাপগুলো আগে থেকে ঠিক করে রাখো। মডেলকে নিজে পথ বাছতে দাও শুধু যেখানে সত্যিই দরকার।Fix the steps in advance wherever you can. Let the model choose its own path only where it is really needed.

10KB memory (Knowledge base)তোমার নিজের ডকুমেন্টের ভান্ডার, যেখান থেকে মডেল তথ্য খুঁজে উত্তর দেয়।

Your own store of documents, which the model searches to answer questions.

  • মডেল শুধু ট্রেনিংয়ের সময়ের তথ্য জানে; অফিসের পলিসি বা আজকের তথ্য জানে না।A model only knows what it saw during training; it doesn’t know your office policies or today’s information.
  • তাই ডকুমেন্ট টুকরা করে, খোঁজার উপযোগী করে আলাদা জমা রাখা হয়।So documents are split into pieces, made searchable and stored separately.
  • প্রশ্ন এলে এখান থেকে দরকারি অংশ খুঁজে মডেলকে দেওয়া হয়; এই পুরো পদ্ধতির নাম RAG।When a question comes in, the relevant parts are found here and given to the model; this whole method is called RAG.

11RAGপ্রশ্ন এলে আগে তোমার ডকুমেন্ট থেকে দরকারি অংশ খুঁজে আনা হয়, তারপর মডেল সেটা দেখে উত্তর লেখে।

When a question comes in, the relevant parts of your documents are found first, then the model writes the answer from them.

  • এর দুইটা ভাগ: আগে থেকে একবার ডকুমেন্টগুলো খোঁজার উপযোগী করে সাজানো, আর প্রতিটা প্রশ্নে সেখান থেকে খুঁজে আনা।It has two parts: preparing the documents for search once in advance, and retrieving from them for every question.
  • মডেলকে নতুন করে শেখাতে হয় না, তবুও সে তোমার অফিসের বা আজকের তথ্য দিয়ে উত্তর দিতে পারে।The model doesn’t need retraining, yet it can answer with your office’s or today’s information.
  • উত্তরের সাথে দেখানো যায় তথ্যটা কোন ডকুমেন্ট থেকে এসেছে, তাই যাচাই করা সহজ।The answer can show which document the information came from, so it is easy to verify.

12Tokenমডেল লেখাকে ছোট ছোট টুকরায় ভাগ করে পড়ে আর লেখে। এই টুকরাগুলোর নামই token।

A model reads and writes text in small pieces. These pieces are called tokens.

  • একটা token কখনো পুরো শব্দ, কখনো শব্দের একটা অংশ, কখনো শুধু একটা চিহ্ন।A token can be a whole word, part of a word, or just a symbol.
  • মডেল ব্যবহারের খরচ, উত্তরের গতি আর মডেল একবারে কতটুকু পড়তে পারে, সবকিছু token গুনে হিসাব হয়।The cost of using a model, the speed of answers and how much it can read at once are all counted in tokens.
  • বাংলায় একই কথা লিখতে ইংরেজির চেয়ে বেশি token লাগে, তাই খরচ বেশি। আর লম্বা নম্বর ভেঙে যায় বলে মডেল অঙ্কে ভুল করতে পারে।Bangla needs more tokens than English for the same sentence, so it costs more; and long numbers get split, so models can make arithmetic mistakes.

13Context windowমডেল একবারে সর্বোচ্চ কতটুকু লেখা দেখতে পারে, তার সীমা। token দিয়ে মাপা হয়।

The maximum amount of text the model can see at once, measured in tokens.

Running meaning-based search and exact-word search together, then merging the results.

  • একটার দুর্বলতা আরেকটা পূরণ করে: একটা অর্থ বোঝে, আরেকটা হুবহু কোড আর নম্বর ধরে।Each covers the other’s weakness: one understands meaning, the other catches exact codes and numbers.
  • দুই তালিকা মেলানো হয় RRF পদ্ধতিতে: কোন ডকুমেন্ট কোন তালিকায় কত নম্বরে আছে, সেটা দেখে নতুন ক্রম বানানো।The two lists are merged with RRF: a new order is made from each document’s position in each list.
  • যে ডকুমেন্ট দুই তালিকাতেই ওপরের দিকে আছে, সেটাই চূড়ান্ত তালিকায় সবার আগে আসে।A document near the top of both lists comes first in the final list.
উদাহরণ · Example“TXN-88213-এ টাকা কেটেছে কিন্তু পৌঁছায়নি”: নম্বরটা শব্দ দিয়ে, আর “পৌঁছায়নি”-র অর্থ embedding দিয়ে ধরা হয়“Money was deducted for TXN-88213 but didn’t arrive”: the number is caught by word search, and the meaning of “didn’t arrive” by embedding

25Fuse ও Rerankবিভিন্ন খোঁজার ফলাফল এক তালিকায় আনা, তারপর আরও যত্ন করে পড়ে সবচেয়ে কাজের কয়েকটা বেছে নেওয়া।

Combining the results of different searches into one list, then reading them more carefully to pick the most useful few.

  • Fuse মানে মেলানো: সব তালিকা এক করা, একই জিনিস দুইবার থাকলে একটা বাদ দেওয়া, আর প্রতিটার পুরো লেখা নিয়ে আসা।Fuse means merging: combining all lists, removing duplicates, and fetching each item’s full text.
  • Rerank মানে আবার সাজানো: একটা আলাদা মডেল প্রশ্ন আর প্রতিটা ডকুমেন্ট পাশাপাশি পড়ে নম্বর দেয়। ধীর, কিন্তু অনেক নির্ভুল।Rerank means re-ordering: a separate model reads the question and each document side by side and scores them. Slower, but much more accurate.
  • ছাঁকনির মতো কাজ করে: লাখ লাখ থেকে আগে 100টা, তারপর 20টা, শেষে সেরা 5টা মডেলের কাছে যায়।It works like a sieve: from millions, first 100, then 20, and finally the best 5 go to the model.
উদাহরণ · Exampleচাকরিতে আগে HR দ্রুত CV ছাঁকে, তারপর টিম লিড মন দিয়ে পড়ে সেরা 5 জন বাছেনIn hiring, HR quickly screens CVs first, then the team lead reads carefully and picks the best 5

26RAG vs CAG vs Fine-tuningমডেলকে নিজের তথ্য দেওয়ার তিনটা উপায়: দরকার হলে খুঁজে আনা, আগে থেকেই পুরোটা পড়িয়ে রাখা, বা মডেলকে শিখিয়ে দেওয়া।

Three ways to give a model your information: fetch it when needed, load all of it in advance, or teach it to the model.

  • RAG ভালো যখন তথ্য অনেক বেশি, প্রায়ই বদলায়, বা সবাই সব তথ্য দেখতে পারবে না। প্রতিবার শুধু দরকারি অংশটুকু খুঁজে আনা হয়।RAG is best when there is a lot of information, it changes often, or not everyone may see everything. Only the needed part is fetched each time.
  • CAG ভালো যখন তথ্য অল্প, প্রায় বদলায় না, আর সবার জন্য একই। পুরো তথ্য একবারেই মডেলকে পড়িয়ে মনে রাখা হয় (cache), তাই প্রতিবার খুঁজতে হয় না।CAG is best when the information is small, rarely changes and is the same for everyone. All of it is given to the model once and remembered (cached), so there is no search each time.
  • Fine-tuning দিয়ে তথ্য না, মডেলের কথা বলার ধরন বা লেখার ফরম্যাট শেখানো হয়। বাস্তবে অনেক সময় এগুলো একসাথে ব্যবহার হয়।Fine-tuning teaches the model’s way of speaking or its output format, not facts. In practice these are often combined.
উদাহরণ · ExampleRAG = দরকার হলে লাইব্রেরি থেকে বই আনা; CAG = ছোট একটা হ্যান্ডবুক সবসময় টেবিলে খোলা রাখা; Fine-tuning = মুখস্থ করে ফেলাRAG = fetching a book from the library when needed; CAG = keeping a small handbook open on the desk; Fine-tuning = memorising it

27Model selectionকাজের জন্য ঠিক মডেল বাছাই। সবচেয়ে বড় মডেল সবসময় সবচেয়ে ভালো পছন্দ না।

Choosing the right model for the job. The biggest model is not always the best choice.

  • নিজের আসল ডাটা থেকে কিছু প্রশ্ন আর সঠিক উত্তর বানিয়ে মডেলগুলোকে পরীক্ষা করো। ইন্টারনেটের র‍্যাঙ্কিং দেখে বেছো না।Make some questions with correct answers from your own real data and test the models. Don’t choose from internet rankings.
  • যে সবচেয়ে সস্তা মডেল তোমার কাজ ঠিকমতো করতে পারে, সেটাই নাও। সহজ প্রশ্ন ছোট মডেলে আর কঠিন প্রশ্ন বড় মডেলে পাঠানো যায়।Take the cheapest model that does your job properly. Easy questions can go to a small model and hard ones to a big model.
  • উত্তর দেওয়ার মডেল, embedding model আর rerank মডেল তিনটা আলাদা করে বাছতে হয়। বাছার পর ঠিক কোন সংস্করণ, সেটা লিখে রাখো।The answering model, the embedding model and the rerank model are chosen separately. After choosing, record the exact version.
উদাহরণ · Exampleসহজ প্রশ্ন ছোট মডেলে, কঠিন প্রশ্ন বড় মডেলেEasy questions to a small model, hard questions to a big one

28Ingestion ও Chunkingবিভিন্ন জায়গা থেকে ডাটা এনে পরিষ্কার করা, তারপর নিয়ম মেনে ছোট ছোট টুকরা করা। RAG-এর ভিত্তি এটাই।

Bringing data in from different places, cleaning it, then cutting it into small pieces by rule. This is the foundation of RAG.

  • ধাপগুলো: ফাইল থেকে লেখা বের করা → বাড়তি জিনিস বাদ দেওয়া → লেখা আর নম্বর একই রূপে আনা → কে দেখতে পারবে তা লিখে রাখা → ব্যক্তিগত তথ্য লুকানো → টুকরা করা।Steps: extract text from files → remove clutter → put text and numbers into one consistent form → record who may see it → hide personal information → split into chunks.
  • টুকরা করার সময় শিরোনাম আর অনুচ্ছেদ মেনে কাটো। টেবিল, প্রশ্ন-উত্তর আর কোড কখনো মাঝখানে কাটবে না।When splitting, follow headings and paragraphs. Never cut tables, Q&A pairs or code in the middle.
  • প্রতিটা টুকরা কত বড় হবে, অনুমান না করে পরীক্ষা করে ঠিক করো। শুরুতে ডাটা খারাপ হলে পরে কোনো ধাপ সেটা ঠিক করতে পারে না।Decide each chunk’s size by testing, not guessing. If the data is bad at the start, no later step can fix it.
উদাহরণ · Example“কর্মীরা 10 দিন ক্যাজুয়াল | ছুটি পাবেন” এভাবে মাঝখানে না কেটে পুরো অনুচ্ছেদ এক টুকরায় রাখাKeep the whole paragraph in one chunk instead of cutting it like “Employees get 10 days of casual | leave”

29Prompt ও Context engineeringPrompt মানে মডেলকে পরিষ্কার নির্দেশ দেওয়া। Context মানে ঠিক করা মডেল একবারে কী কী তথ্য দেখবে।

Prompt means giving the model clear instructions. Context means deciding what information the model sees at once.

  • ভালো prompt-এ থাকে: মডেলের ভূমিকা, কাজটা কী, কী করা যাবে না, উত্তর কেমন হবে, আর দুই-তিনটা উদাহরণ।A good prompt has: the model’s role, the task, what not to do, how the answer should look, and two or three examples.
  • Context সাজানোর কৌশল: শুধু দরকারি তথ্য রাখা, লম্বা আলাপ ছোট করে রাখা, বাকিটা বাইরে জমিয়ে দরকারে আনা।Context techniques: keep only needed information, shorten long conversations, and store the rest outside to bring in when needed.
  • বেশি তথ্য দিলেই ভালো না। কম কিন্তু সঠিক তথ্য দাও; স্থির নির্দেশ ওপরে আর প্রশ্নটা সবার শেষে রাখো।More information isn’t always better. Give less but correct information; keep fixed instructions at the top and the question at the very end.

At its core, what does a large language model (LLM) do?

  1. কইন্টারনেটে উত্তর খোঁজেSearches the internet for answers

  3. গএকটা নির্দিষ্ট ডাটাবেজ থেকে উত্তর তোলেLooks up answers in a fixed database

সে শুধু হিসাব করে, পরের শব্দ কোনটা হওয়ার সম্ভাবনা সবচেয়ে বেশি।It only calculates which word is most likely to come next.

  2. খএকটা পূর্ণ বাক্যOne full sentence
  3. গলেখার ছোট টুকরা, যেমন একটা শব্দ বা শব্দের অংশA small piece of text, like a word or part of a word

যেমন “unhappiness” ভেঙে “un” + “happiness” হতে পারে।For example, “unhappiness” may be split into “un” + “happiness”.

মডেল লেখা পড়ে আর লেখে token হিসেবে।The model reads and writes text as tokens.

4‘Temperature’ কমালে মডেলের আউটপুট কেমন হয়?

Lowering the ‘temperature’ setting makes the model’s output:

  1. কলম্বাLonger
  2. খদ্রুতFaster
  3. গবেশি সৃজনশীল ও এলোমেলোMore creative and random
  4. ঘবেশি সামঞ্জস্যপূর্ণ ও অনুমানযোগ্যMore consistent and predictable
উত্তর · Answerঘ) বেশি সামঞ্জস্যপূর্ণ ও অনুমানযোগ্যd) More consistent and predictable
কেন · Why

Temperature গতি নিয়ন্ত্রণ করে না, নিয়ন্ত্রণ করে randomness।Temperature does not control speed; it controls randomness.

কম temperature-এ মডেল প্রায় সবসময় সবচেয়ে সম্ভাব্য token বেছে নেয়, তাই একই প্রশ্নে প্রায় একই উত্তর আসে।At a low temperature the model almost always picks the most likely token, so the same question gets nearly the same answer.

বেশি temperature-এ উত্তর সৃজনশীল, আবার এলোমেলোও হয়।At a high temperature answers become more creative, but also more random.

এজন্য RAG বা অফিসের তথ্যের উত্তরে temperature 0 থেকে 0.2 রাখা হয়।That is why RAG and factual answers use a temperature of 0 to 0.2.

6RAG-এর পূর্ণরূপ কী?

What does RAG stand for?

  2. খRandom Answer Generator
  3. গRule-Assisted Grammar
  4. ঘRecursive AI Graph

অর্থাৎ তথ্য খুঁজে এনে প্রম্পটে যোগ করে উত্তর বানানো।In short: fetch information, add it to the prompt, then generate the answer.

মডেল শুধু ট্রেনিংয়ের সময়ের তথ্য জানে।The model only knows what it saw during training.

RAG প্রশ্ন অনুযায়ী তোমার ডকুমেন্ট থেকে তথ্য এনে দেয়।RAG fetches information from your documents for each question.

8‘Embedding’ কী?

What is an ‘embedding’?

  1. কলেখার কমপ্রেস করা ZIPA compressed ZIP of text
  2. খলেখার অর্থ বোঝানো সংখ্যার তালিকাA list of numbers representing the meaning of text
  3. গএনক্রিপ্ট করা মেসেজAn encrypted message
  4. ঘLLM-এর লেখা সারাংশA summary written by the LLM
উত্তর · Answerখ) লেখার অর্থ বোঝানো সংখ্যার তালিকাb) A list of numbers representing the meaning of text
কেন · Why

ZIP জায়গা বাঁচায়, আর তা থেকে হুবহু মূল লেখা ফেরত পাওয়া যায়।A ZIP saves space, and the exact original text can be restored from it.

Embedding অর্থ ধরে, আর তা থেকে মূল লেখা ফেরত আনা যায় না।An embedding captures meaning, and the original text cannot be restored from it.

“ছুটি” আর “leave”-এর embedding কাছাকাছি হবে, কারণ দুটোর অর্থ এক।The embeddings of “ছুটি” and “leave” are close because they mean the same thing.

10চ্যাটবট আগের মেসেজ কীভাবে “মনে রাখে”?

How does a chatbot ‘remember’ earlier messages in a conversation?

  1. কমডেল সেগুলো নিজের weights-এ জমা রাখেThe model saves them in its weights
  2. খপ্রতিটা নতুন রিকোয়েস্টের সাথে অ্যাপ পুরো কথোপকথন আবার পাঠায়The app sends the conversation history with every new request
  3. গGPU সেগুলো চিরকাল cache করে রাখেThe GPU caches them forever
  4. ঘমনে রাখে না; সব চ্যাটবট ভুলে যায়It doesn’t; every chatbot forgets
উত্তর · Answerখ) প্রতিটা নতুন রিকোয়েস্টের সাথে অ্যাপ পুরো কথোপকথন আবার পাঠায়b) The app sends the conversation history with every new request
কেন · Why

মডেল নিজে কিছুই মনে রাখে না (stateless)।The model itself remembers nothing (it is stateless).

প্রতিবার অ্যাপ আগের সব মেসেজ নতুন প্রশ্নের সাথে context window-এ জুড়ে পাঠায়।Each time, the app adds all earlier messages to the context window with the new question.

KV cache শুধু একটা উত্তর বানানোর সময়টুকুর জন্য, চিরকালের জন্য না।The KV cache only lasts while one answer is being generated, not forever.

এজন্য লম্বা চ্যাটে context window ভরে যায় আর শুরুর কথা হারিয়ে যায়।That is why long chats fill the context window and the earliest messages get lost.
